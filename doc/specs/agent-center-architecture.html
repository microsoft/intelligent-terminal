INTELLIGENT TERMINAL / TARGET ARCHITECTURE

管理工作，而不是管理工具。

Terminal is the easiest way to get tasks done on your OS.
保留一个对话入口和按需使用的 shell，把“理解意图”与“可靠推进工作”分开：Agent 提出方案，工作服务持有事实、校验权限并驱动执行。

理解与规划 工作服务 / 权威状态 执行资源 / 现场 验证 / 人的控制 实线箭头：请求与执行 · 虚线箭头：观测与回传

对原图的关键修正：delegate 变为受校验的提议与派发；publish 拆成有来源的进度/证据回传和需要人处理的待办。 Work 是持久领域对象，不是自己“发布状态”的进程。普通人工 shell 命令也不会自动变成已验证的 Work 结果。

原图还缺的，不是更多 Agent，而是这些责任。

① 确定性的工作控制层

Orchestration Agent 擅长理解与推理，但不应该独占状态或自行授权。服务负责校验、调度、事件驱动、预算、取消与去重；Agent 重启后工作仍然存在。

② 完整的 Work 模型

不只是 status + agents + shell。还要有目标、完成条件、位置、上下文、计划与依赖、授权、决定和证据。资源通过身份关联，而不是每个 Work 必须捆绑一套 shell。

③ 持久状态与上下文连续性

保存工作事实、输入版本、事件、操作回执与结果。模型会话不是数据库；换执行者不应要求用户转贴上下文。未知副作用必须先核对，不能直接重跑。

④ 检查、返工与交付闭环

执行者提交，检查者依据固定输入验证，失败自动回到协调流程。内部通过只产生候选交付；最终验收与必要的交付回执完成后，才能记录工作完成。

⑤ 人的决定与注意力

全局待办解释“为什么找你”。用户可询问方案、改变方向、暂停、接管和验收；这些操作绑定具体工作与版本，不能只得到一句“好的”，也不能抢走另一工作的输入。

⑥ 受管的 OS 执行边界

明确 Agent、shell、文件、应用资源在哪里运行，谁有写入权，如何停止和恢复。已有进程可见不等于可接管；OS 任务要验证实际目标状态，不能用报告代替真实效果。

这是补齐职责的目标图，不代表这些模块都是新缺失的代码。

当前实现已具有工作引擎、持久存储、运行适配器、检查与交付等基础。首个试点是本地 LocalCode / Report。全局事实对话、完整自主返工、输入可靠性等是否完成，以对应验收记录为准。

更广泛的 OS / 应用状态操作、已有现场纳管和执行者更换后的连续性，需要逐适配器资格验证。 “所有资源可调度”始终指已注册、已授权、可确认身份和所有权的资源，而不是无限权限。
